# Статистика исторических пар — первая версия

## Как пользоваться

1. Откройте «Статистика» в главном меню, блок «Торговля», над «Роботы».
2. Укажите папку конкретного датасета, содержащую `Settings.txt`, затем
   «Загрузить каталог». Не корневую папку Data и не отдельный файл свечей.
3. Выберите A и B. Для первого сценария A — нужная серия SR (обыкновенный Сбер),
   B — соответствующая серия SP (привилегированный). Названия отображаются
   из Settings; автоматического подбора или склейки серий нет.
4. Выберите общий таймфрейм. В списках доступны только реально имеющиеся
   итоговые текстовые свечные файлы. Даты можно оставить пустыми для всей истории.
5. Задайте отдельно для обеих ног минимальный дневной объём и число активных
   свечей, а также минимальное покрытие. Нажмите «Рассчитать A − B».

Начальные значения 1 / 1 / 1 / 1 / 80% демонстрационные. Один контракт объёма
не делает инструмент ликвидным. Подберите пороги по дневной диагностике
для своего таймфрейма и инструмента. Фильтр по свечам оценивает активность,
а не доступность объёма в стакане и не исполнимость арбитража.

## Что именно считается

`Спред = Close(A) − Close(B)` при одинаковой метке времени и положительном
объёме обеих свечей. Никакого заполнения пропусков и поиска ближайшего времени.
Сопоставимость единиц цен, валют, экспираций и часовых поясов проверяет пользователь.
Коэффициенты равны 1; результат — единицы исходной котировки, не PnL в рублях.

За каждый календарный день исходных меток считаются объёмы/активные свечи каждой
ноги. Покрытие = совпавшие активные метки / объединение активных меток × 100%.
День принимается, только если обе ноги достигают своих порогов и есть хотя бы
одна общая активная точка. Пороги включительные. Дневной фильтр ретроспективный.
Покрытие не измеряет полноту торговой сессии; отсутствующие в обоих файлах свечи
невидимы анализатору. Временные зоны не пересчитываются.

Результаты:

- Сводка: число точек, фактическое начало/конец, минимум, максимум, размах,
  невзвешенное среднее по точкам, стандартное отклонение по генеральной совокупности (N).
- «Диагностика по дням»: все наблюдаемые дни, включая отклонённые, объёмы,
  активные свечи, совпадения, покрытие, первое нарушенное условие фильтра,
  дневные min/max/размах для принятых дней.
- «Принятые участки»: статистика смежных принятых календарных дат. Пропущенный
  календарный день или отклонённый день разрывает участок, в том числе выходной.
- «Все точки спреда»: все допущенные точки, без усечения; таблицы виртуальные
  и имеют вертикальную/горизонтальную прокрутку.

Размах = max − min по допущенным Close-разностям, а не реальный внутрисвечной
размах исполнимого спреда. Совпадение меток начала свечей не означает
одновременные последние сделки. `High(A) − Low(B)` для этих целей не используется.
Пустой результат показывается сообщением, а не ложными нулевыми показателями.

## Формат и безопасность

Структура: `<датасет>/<имя инструмента>/<таймфрейм>/<имя инструмента>.txt`.
Имена очищаются по файловому соглашению OsData. Поддерживаются текущие и старые
строки Settings с полными именами. Состояние переключателей загрузки не скрывает
уже скачанные файлы. Отсутствующие файлы не создаются. Temp, тики и стаканы
не читаются как свечи. Символические ссылки/переходы по каталогам запрещены.

Свеча: `DATE,TIME,OPEN,HIGH,LOW,CLOSE,VOLUME[,OPEN INTEREST]` без строки заголовка.
Дата `yyyyMMdd`, время `HHmmss`, десятичная точка. OI необязателен, валидируется,
но не используется при фильтрации. Отрицательные цены разрешены, объёмы — нет.
Некорректные OHLC, дубликаты и убывающие метки — ошибка с файлом и номером строки.
Даже строки вне выбранных дат проверяются, чтобы не скрывать повреждение файла.

Перед анализом остановите обновление датасета. Обе ноги открываются только для
чтения с запретом конкурентной записи до завершения расчёта. Ни Settings, ни
исходная история не изменяются. Создания OsDataSet/загрузчиков/серверов нет.
Доступна отмена; закрытие окна отменяет работу и не публикует поздний результат.
Изменение параметров очищает старый результат. Одновременно — одна операция.

Защитный предел — 2 000 000 выбранных свечей на ногу. При превышении сузьте даты
или выберите более крупный готовый таймфрейм. Лимит не означает гарантии малого
потребления памяти: две большие истории и результат занимают сотни МБ.
График, экспорт, нормализация лотов, автосклейка и другие анализы — следующие этапы.

## Проверка разработчиком

Архитектура — `adr/0001-offline-pair-statistics.md`; её ревью — `adr/0001-review.md`.
Ревью реализации и фактический статус проверок — `statistics-review.md`.
Автотесты — `Tests/Statistics/` (чистое ядро, не MCP), включены в решение.
Ветка `feature/statistics-pair-analysis` имеет Windows CI для тестов и сборки,
если Actions разрешены в форке. MCP-стенд не запускается.

Ручная приёмка на Windows:

- Открыть окно повторно: остаётся один экземпляр; закрыть и открыть заново.
- Проверить блокировку кнопки при парольной блокировке главного меню.
- Выбрать реальный датасет, SR/SP одной экспирации, одинаковый таймфрейм.
- Сверить несколько точек вручную, включая отрицательную разность, и дневной
  размах; увеличить пороги и убедиться, что дни/точки исключены.
- Проверить разные даты, отсутствие общих свечей, пустой каталог, файл с ошибкой.
- Ввести `abc` в числовой порог и некорректную дату: расчёт не стартует.
- Отменить длинный расчёт; закрыть окно во время чтения; открыть заново.
- Переключить RU/EN и темы при открытом окне; проверить подписи, таблицы,
  прокрутку и изменение размеров. Сравнить историю/Settings до и после анализа.
