# Отдельные окна таблиц Order Flow

Граница этой реализации по уточнению владельца: **только
`OsEngine/OsData/OrderFlow/` и его подкаталоги**. Она не переносит таблицы
остальных модулей OsEngine и не означает выполнения глобального задания
`UI-DETACHED-TABLES-001`. Общие темы, фабрики таблиц и торговые экраны не меняются.

## Как пользоваться

1. В Order Flow или «Исследование Cloud» выберите нужный раздел.
2. Нажмите **«Открыть таблицу: …»**. Даже пустая таблица открывается; рядом
   показан счётчик, а в окне — контекст результата. При отсутствии данных
   сначала рассчитайте или откройте сохранённое исследование.
3. Меняйте размер окна, сортируйте столбцы, выбирайте строки. Для Cloud 1/2
   фильтры находятся также над таблицей. Они по-прежнему меняют признаки PASS
   и показ графика, а не удаляют строки из списка. В Explorer доступны
   страницы, поиск ID и прежние действия соответствующего раздела.
4. Для параметров Explorer редактируйте столбец «Значение». Расчёт или
   применение видимости запускаются только явной командой. Закрытие таблицы
   не запускает расчёт; незавершённая невалидная WPF-правка не позволяет
   закрыть окно — исправьте значение либо отмените правку клавишей Esc.
   Содержательная проверка диапазонов остаётся при запуске существующей команды.
5. «К исходному экрану» возвращает к разделу таблицы. Повторное открытие
   активирует уже открытое окно. Крестик закрывает только представление;
   повторное открытие показывает текущие данные и сохраняет состояние того
   же DataGrid. Закрытие рабочего экрана закрывает его таблицы.

Окна таблиц немодальные, без `Owner` и `Topmost`: можно продолжать ввод
в основном окне и переключаться между приложениями. Исходные блокировки
реплея и доступности команд сохраняются. Текстовые отчёты, карточки сценариев
и графики не являются таблицами и остаются на своих местах.

В Cloud настройки больше не ограничены строкой высотой 220 px; кнопки имеют
автоматическую высоту. При маленьком окне используйте прокрутку рабочей
области. В основном Order Flow горизонтальная прокрутка сохраняет доступ
к существующим широким сеткам параметров; разметка других экранов не меняется.

## Реестр перенесённых таблиц

Все 20 таблиц создаются XAML в двух указанных экранах, доступны в офлайн-модуле
Order Flow из Os.Data, а не как новые Live/Tester/Optimizer торговые компоненты.
В каждой строке результат переноса одинаков: вместо встроенной таблицы —
именованная кнопка и счётчик; исходный DataGrid помещается в отдельное окно.
Модели, обработчики, сортировка и виртуализация не дублируются. Родительский
экран владеет данными; временное окно владеет только представлением и панелью
команд. Обновление результата меняет те же ItemsSource и контекст окна.

Сводка, сравнение групп, качество поиска, текст карточки, поля ввода,
выпадающие списки и непрерывные графики исключены: это не табличные элементы.
WinForms-таблиц и динамических фабрик таблиц в этой границе нет.

## Проверка и ограничения evidence

Из каталога `project/`, при закрытом приложении:

```powershell
dotnet build OsEngine/OsEngine.csproj
dotnet run --project OsEngine/OsData/OrderFlow/DetachedTables/Verification/DetachedTables.Checks.csproj
dotnet run --project Tests/OrderFlowResearch/OsEngine.OrderFlowResearch.Tests.csproj
```

Локальный harness компилирует `Checks.cs.fixture` явно: этот файл не попадает
в production-компиляцию. Его промежуточные и исполняемые файлы находятся в
`%TEMP%/OsEngine-OrderFlow-DetachedChecks/`, вне дерева production-кода.
Используется существующая friend-assembly граница офлайн-тестов; общие
assembly attributes не меняются. Harness проверяет перенос/повторное
открытие, блокировки, WPF-валидацию, освобождение таймера, исходный sender
команд, связанность фильтров, регистрацию 15 + 5 таблиц, реальные стили
Button/TextBox в двух темах и несколько размеров layout. Это не запуск
основного приложения, коннектора или торгового стенда.

Фактическая ручная приёмка мышью/клавиатурой при 100%, 125%, 150% Windows DPI,
в восстановленном/развёрнутом окне и на пользовательских исследованиях
остаётся **REQUIRES OWNER-RUN**. Компонентные размеры в DIP не заменяют её.
Проверить все строки реестра: открыть, изменить размер, прокрутить, выбрать
строку; для настроек — исправить значение и применить; закрыть/переоткрыть,
сменить результат, запустить/остановить реплей, закрыть рабочий экран.
Расчёты/форматы/торговые правила не изменяются; открытие таблицы не доказывает
прибыльность или Tester/live parity.
