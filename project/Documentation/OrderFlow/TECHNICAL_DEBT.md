# ORDER-FLOW-TECH-DEBT-001: отложенный технический долг

**Статус:** CURRENT BACKLOG — не перечень исправленных дефектов.

## TD-CLOUD-WINDOW-001 — Cloud перекрывает Order Flow и блокирует ввод

**Состояние:** OPEN / DEFERRED BY OWNER.
**Дата сообщения и решения:** 24.09.2026.
**Область:** OsData → Order Flow → «Исследование Cloud», оконный ввод и фокус.

По ручной проверке владельца после попытки исправления окно «Исследование
Cloud» по-прежнему находится поверх Order Flow и блокирует ввод в нём.
Владелец явно попросил отложить дальнейшее исправление и выполнить commit/push
текущих изменений. Дефект не закрыт; причина сохраняющегося поведения не
установлена. Агент повторно не воспроизводил его в запущенном приложении.

### Сценарий для повторной проверки

1. Открыть OsData, затем Order Flow.
2. Нажать «Исследование Cloud» и оставить его окно открытым.
3. Переключиться в Order Flow, попробовать изменить файл/шаг цены/даты.
4. Проверить выбор источника и ввод в OsData, а также переключение с внешним
   приложением. Эти дополнительные пути требуют отдельной проверки.

Ожидается свободное переключение и доступный ввод при открытом Cloud.
Сообщённый фактический результат на шаге 3: Cloud остаётся впереди, ввод в
Order Flow заблокирован. Наличие явного `Topmost` само по себе не установлено
как причина этого результата.

### Что уже изменено, но не закрыло дефект

В diff поверх `67b0dc904980b4193c5e53fef92cb454f0dfd937` запуск Order Flow
переведён на `Show()`, из Cloud и вынесенных графиков удалён WPF `Owner`,
из 92 XAML-окон удалён `Topmost="True"`. Сохранено явное закрытие связанных
окон. Это факты кода, а не доказательство исправления пользовательского сценария.

Сборка решения прошла без ошибок; offline-набор — 144/144, валидатор — 109/109.
Эти проверки не показывают настоящие окна ОС и не доказывают доступность ввода
или правильный порядок окон. Прежний вывод `CLEAN` относится к статическому
review; последующая ручная проверка владельца не подтвердила исправление.

### Условия закрытия техдолга

При отдельном возобновлении задачи установить точный запущенный executable и
сценарий, воспроизвести блокировку и определить её источник. Закрывать запись
только после ручной проверки, что Order Flow и OsData принимают ввод при
открытом Cloud, окна нормально переключаются, повторное открытие не создаёт
дубликаты, а закрытие родительского рабочего окна освобождает связанные окна
и расчёты. До такого подтверждения запись остаётся открытой.

Временный порядок работы: задавать входные параметры до открытия Cloud.
Закрытие Cloud освобождает его рабочую область и отменяет его текущую работу;
не следует рассчитывать на сохранение незавершённого расчёта при закрытии.
