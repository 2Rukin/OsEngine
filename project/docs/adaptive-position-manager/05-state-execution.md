# 05. Состояния, исполнение и учёт

Навигация: [индекс](README.md). При конфликте обычной политики с безопасностью действует этот документ и [01](01-product.md).

## Два независимых состояния

Жизненный цикл кампании: Idle → Preflight → Entering → Active → Closing → Completed. Дополнительные состояния: PausedNoIncrease, Reconciling, FaultedClosing. Отдельно хранится MarketRegime: NORMAL / FAST_FAVORABLE / FAST_ADVERSE. NoAddZone и data readiness — разрешения, не новые завершённые кампании.

| Состояние | Разрешено | Запрещено |
|---|---|---|
| Preflight | Проверка данных, риска, метаданных и границ | Отправка до успешной проверки |
| Entering | Учёт каждого fill; защита уже исполненной части; отмена остатка | Полный начальный объём в учёте до исполнения; обычное усреднение |
| Active | Обратимые ADD/REDUCE с допусками | Второй владелец позиции; переворот |
| PausedNoIncrease | Отмена набора, защитное уменьшение, сверка | Новый ADD/вход |
| Reconciling | Сопоставление брокера, движка и сохранённых intents | Слепой повтор неизвестной заявки |
| Closing / FaultedClosing | Отмена несовместимых ордеров и доведение подтверждённой позиции до нуля | Возврат к обычному набору |
| Completed | Просмотр отчёта | Повторная активация по старому EntrySignalId |

ExitLatch устанавливается до отправки защитных команд и необратим для CampaignId. Поздний fill после Completed вызывает защитную сверку/закрытие, но не возобновляет стратегию. Completed требует одновременно нулевого остатка и отсутствия потенциально исполнимых заявок кампании, подтверждённых сверкой.

## Арбитраж одного события

Сначала учесть новые подтверждённые broker/fill events. Затем проверить ручной аварийный выход, HardStop, денежный стоп, обязательный session exit и окончательную цель. После этого readiness, доступный риск, запреты ADD, режим рынка и hysteresis. Сформировать один Decision с полным набором reason codes и сохранить intent до отправки. UI не вызывает торговые методы в обход контроллера.

Решение «ждать» не отменяет автоматическую защиту. Первое частичное исполнение начального входа уже должно быть защищено. Нельзя ждать только PositionOpeningSuccesEvent для защиты фактически набранной части, если его семантика отложена до полного исполнения.

## Обычные заявки

Один обычный working intent на кампанию. Изменение target при активной заявке приводит к сравнению с её остатком: оставить, запросить отмену или заменить после подтверждения. PendingCancel остаётся потенциально исполнимым. Target учитывает pending, но risk capacity освобождают только фактические сокращения/подтверждённые отмены.

Выход из Long исполняется сокращением собственной позиции, а не произвольным SellAtMarket, способным открыть Short. Для Short симметрично. ReducibleVolume — подтверждённый остаток минус уже зарезервированный на закрытие объём; отрицательное значение является ошибкой сверки. При поддержке reduce-only использовать её, но не считать доступной во всех коннекторах.

Лимитный режим: срок жизни, политика перепостановки, максимальная частота изменений и допустимое отклонение от target задаются заранее. Снятие лимитки при импульсе имеет задержку и может завершиться поздним fill. Виртуальный SKIP применяется только к ещё не исполненным действиям. Не выставлять заранее всю лестницу и одновременно обещать свободно пропустить её постфактум.

MaxChildVolume ограничивает обычные действия. Один резкий скачок не означает отправку всех детей в цикле по тому же snapshot. Новая обычная заявка требует нового события/таймера и сверки. Это ограничение не используется для искусственной задержки аварийного выхода.

## Защитное закрытие

Устанавливается ExitLatch; запрещаются новые увеличения; запрашивается отмена входных и конфликтующих выходных заявок. Одновременно при доступной инфраструктуре начинается закрытие подтверждённого незарезервированного остатка. Не ждать бесконечно отмены ADD перед защитой уже открытой части. Каждое позднее исполнение вновь учитывается и, при необходимости, закрывается.

Контроллер должен исключить двойное закрытие одной части при гонке с ранее отправленным REDUCE. При неопределённом статусе сначала запросить фактические заявки/позицию; независимая брокерская защита остаётся предпочтительнее слепого дублирования. Таймаут не доказывает ни отмену, ни отсутствие исполнения.

Market означает намерение приоритетного выхода, не гарантию немедленного fill или цены. Если коннектор эмулирует Market агрессивным Limit, это фиксируется capability и проверяется отдельно. При остановке торгов/лимитах цены/отсутствии связи остаётся FaultedClosing, видимая незакрытая позиция и операторское предупреждение. Нельзя рисовать ноль на основании отправки команды.

## Ledger и результат

Для наращивания на a по P: новый средний Bnew=(qB+aP)/(q+a). При сокращении r по P реализованный gross PnL увеличивается на d·r·(P−B)·c; средняя цена оставшегося объёма не меняется. Все комиссии и корректировки учитываются ровно один раз. Для линейной модели полная equity кампании равна RealizedNet+d·q·(Pmark−B)·c за вычетом ещё не учтённых издержек оценки.

Дополнительно сверять денежное равенство по signed fills: NetPnL при полном закрытии = −c·Σ(SignedFillQty·FillPrice)−ΣFees, где SignedFillQty положителен для покупки. При открытом остатке добавляется c·NetSignedQty·Pmark. Для фьючерсного клиринга/смены метаданных valuation adapter должен исключить двойной учёт вариационной маржи и цены входа.

Lot attribution (FIFO/LIFO/виртуальные порции) разрешена только как дополнительный аналитический разрез, полностью сверяемый с общим результатом. Продавать «прибыльные последние лоты» и скрывать убыток оставшейся части нельзя. RealizedNet отрицательный расходует бюджет; положительный по умолчанию не увеличивает его.

## Сохранение и рестарт

Сохранять Spec/version, A/S/U, ExitLatch, режим, warmup/checkpoint, PolicyTarget/hysteresis, intents/client keys, fills и позиции сверки. Запись intent предшествует отправке. После crash между отправкой и ack восстанавливать через доступные broker identifiers и список заявок, не переотправлять автоматически.

Ключи дедупликации fills должны соответствовать реальным гарантиям коннектора. Корректировки и отмена сделки — отдельные события ledger. После reconnect сбросить книгу и прогреть признаки; до завершения сверки только NoIncrease. Если адаптер не предоставляет достаточных данных восстановления, live-режим не допускается, а ограничение явно сообщается.

## Чужие позиции и вмешательство

M1 использует выделенный tab и campaign ownership. Закрывать весь счёт методом CloseAll без доказанной изоляции запрещено. Ручное изменение позиции, другой робот на том же netting-счёте или расходящийся брокерский объём вызывает Reconciling. Автоматическое присвоение чужого объёма менеджеру недопустимо.

## Производительность и потоки

Единственный последовательный владелец состояния получает нормализованные события. Не использовать mutable static для кампаний. UI получает копии snapshots. Переполнение очереди — потеря достоверности, блокировка набора и аварийная диагностика, не тихое удаление fills. Фоновая запись логов не блокирует защитный путь. Причины и факты исполнения обязательны даже при отключённой подробной диагностике.
