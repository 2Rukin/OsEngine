# 04. Данные, контракты и воспроизводимость

Навигация: [индекс](README.md), [математика](03-mathematics.md). Версии схем, алгоритмов очистки и источников обязательны в каждом run manifest.

## Профили данных

| Профиль | Доступно | Недоступно / ограничение |
|---|---|---|
| TradeOnly | Цена, размер и время сделок; торговая дельта при достоверном Side; скорость и realized volatility | Нет настоящего OFI, текущего spread/depth и очереди нашей лимитки |
| BookTopOnly | Изменения лучших bid/ask и размеров; mid, spread, top depth | Нет достоверного потока отдельных сделок/агрессоров |
| SampledBook | Те же величины между сохранёнными снимками | Пропущенные между snapshots события не восстанавливаются; OFI только sampled/proxy |
| SynchronizedTradesBook | Согласованные trades и quote events, доказанная семантика времени/порядка | Само наличие L2 ещё не доказывает позицию нашей заявки в очереди |

TradeOnly обязателен для M1. Включение требующего книги профиля без книги отклоняется до запуска. Нельзя подставлять OFI=0 и depth=1, называя такой прогон полноценным. BookTopOnly и SynchronizedTradesBook добавляются только после T09. «L2» означает рыночные данные, не уровень успешности тестов.

## Входные сделки

Поддерживаемый пользовательский текстовый контракт: Date,Time,Price,Volume,Side,MicroSeconds,Id. В предоставленном образце SRU6 строки идут без заголовка, цена/объём и Buy/Sell присутствуют; MicroSeconds в показанных строках равен 0. Это наблюдение образца, не аудит всего файла и не гарантия микросекундной точности.

Парсер должен объявить точный формат даты/времени, десятичный разделитель, единицы Volume, семантику MicroSeconds и timezone. Id хранить без потери точности (строка либо подходящий целочисленный тип), не преобразовывать через double и не трактовать как UTC timestamp. Side Unknown/None не превращается в Sell. Пример не публикуется целиком в репозитории; рыночные наборы хранятся отдельно с правами доступа и контрольной суммой.

## Порядок событий

Каждая запись получает SourceId, InstrumentId, SessionId, EventTime, ReceiveSequence, SourceSequence при наличии, Payload и QualityFlags. При совпадении EventTime используется доказанный SourceSequence, иначе стабильный исходный порядок. Политика одинакова в test/live; доступная live receive-order может отличаться от ретроспективной сортировки файла, это отмечается.

Нельзя сортировать одинаковые секунды по цене или полю Id без подтверждения семантики. Нельзя подавать заявку на начало секунды по результату всех сделок этой секунды. Микросекунды 0 не разрешают делать выводы о задержках меньше секунды.

Дубликаты проверяются по составному ключу источника/сессии/инструмента и его достоверному Id. При неизвестной уникальности — флаг/отчёт, не массовое удаление совпадающих цены и объёма: реальные одинаковые сделки допустимы. Конфликтующие payload одного доказанно уникального Id блокируют набор.

Позднее событие не переписывает уже совершённое решение. Offline-препроцессинг может сортировать только объявленным способом до запуска, формируя новый dataset hash. Live при нарушении порядка действует по явно выбранной политике RejectAndPause; автоматическая смена политики запрещена.

## Прогрев и отсутствие данных

WarmupSeconds, MinSamples, GridSeconds, MaxPriceAge и MaxBookAge фиксируются в профиле. Отсчёт пригоден только при свежей цене на его границе. При stale-состоянии или разрыве последовательности включается NoIncrease, прекращается расчёт недостоверных новых признаков, начинается новый warmup. Защитная логика и сверка остаются активны.

Для δtrade=(BuyVolume−SellVolume)/(BuyVolume+SellVolume) нулевой знаменатель даёт Missing, а не нейтральный сигнал. Доля UnknownSide сохраняется; превышение порога блокирует профиль, использующий торговую дельту. Цена/объём без Side могут быть достаточны только для профиля, не использующего направление агрессора.

Сброс окна на новую сессию обязателен по умолчанию. Недельный контекст допустим как отдельный уже известный feature, но не разрешает перенос позиции через ночь.

## Логические контракты компонентов

| Контракт | Обязательные поля |
|---|---|
| CampaignSpec | Идентификаторы, направление, InitialVolume/MaxVolume, S/U, денежный бюджет, источник входа, session cutoff, version |
| MarketSnapshot | EventTime/sequence, PriceMode, P, актуальные quotes, feature values, readiness/quality, model version |
| PositionSnapshot | FilledVolume, AverageEntry, RealizedNet, комиссия, working/cancel-pending/unknown orders, broker sequence |
| Decision | DecisionId, RawTarget, PolicyTarget, RiskAllowedTarget, EffectiveVolume, Action, Volume, priority, reason codes, feature snapshot hash |
| ExecutionIntent | CampaignId/DecisionId, client key, side, qty, type, limit/expiry, sent/ack status, filled qty, outstanding worst-case risk |
| Fill | BrokerTradeId, order key, price, qty, side, event/receive times, fee, correction flags |
| CampaignResult | Итог и открытая просадка, максимум объёма, оборот, время, издержки, причины выхода, data-quality status |

Названия — проектируемые, не существующие API OsEngine. Фактические C#-типы и адаптеры подтверждает T01. Денежные/ценовые величины — decimal; вещественные статистические вычисления допустимы с проверкой finite и последующим контролируемым преобразованием. Точность не терять на границе JSON/CSV.

## Run manifest

Содержит repository commit, model/schema version, StrategyParameter values, locks, dataset filenames и hashes, входной campaign schedule hash, time range/timezone, warmup rules, source capabilities, price mode, порядок событий, fee/slippage/fill-model version, random seed, valuation metadata, учебные/контрольные интервалы, состояние optional features и версии калибровок.

Разные комиссии, различная сортировка файла или отказ от неизвестного Side означают разные прогоны. При завершении с неполными данными выводится `InvalidForPerformance` или `Partial`, не обычный успешный результат.

## Калибровка OFI и запрет утечки

В [13](13-sources.md) определено исходное OFI. Его расчёт требует последовательных best quotes. Равные цены учитывают изменение размера; при переходе best price меняется вклад старой/новой очереди. После reconnect первая книга задаёт базу, а не огромный искусственный OFI.

Коэффициент современного воздействия Δmid=β·OFI оценивается отдельно от предиктора будущей доходности. Для последнего response — будущий интервал, а признаки заканчиваются строго раньше него. Online fit обновляется только после созревания метки; validation/test не подмешивается в обучение без заранее объявленного causal online protocol.

Depth нормируется один раз: либо β обучен на сыром OFI с учётом depth, либо применяется OFI/depth в отдельной модели. Повторное деление на depth ради «усиления» недопустимо без самостоятельной модели и проверки единиц.
