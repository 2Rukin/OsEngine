# 12. Эксплуатация и выпуск

Это будущий runbook для реализованного продукта. В текущей поставке реальные подключения и торговля не выполнялись. Gate matrix: [10](10-quality-gates.md).

## Preflight перед кампанией

Проверить режим запуска (Tester/Paper/Live), выбранные счёт/инструмент, ownership, capability profile, timezone/cutoff, стоимость шага и валюту, свежесть данных/warmup, InitialVolume/MaxVolume, границы S/U, денежный бюджет, комиссии/slippage reserve и отсутствие неизвестных заявок. Восстановленная кампания не проходит initial entry заново.

Перед live оператор видит план: начальная экспозиция, жёсткая нижняя/верхняя граница, NoAddZone, предел позиции и оценка потерь со стресс-исполнением. Значение RiskBudget не является гарантией максимального фактического убытка. Отсутствие обязательных параметров блокирует запуск.

## Режимы остановки

| Действие | Эффект |
|---|---|
| Пауза набора | Запрещает новые увеличения, отменяет их активные заявки с учётом finality; защита остаётся |
| Продолжить | Только после freshness/warmup/сверки; не действует при ExitLatch |
| Закрыть кампанию | Ставит ExitLatch, закрывает собственный остаток и завершает кампанию |
| Аварийное закрытие | Приоритетное защитное завершение без ожидания обычных фильтров |
| Закрыть окно | Закрывает представление, не скрыто отключает менеджера позиции |
| Остановить приложение | Требует явного решения об открытых позициях и рабочей внешней защите; не равно нулю на бирже |

Действие CloseAll на счёте с чужими позициями запрещено как способ завершения одной кампании.

## Аварии

Disconnect/stale stream: NoIncrease, предупреждение, запрос отмены набора при возможности, сохранение состояния, продолжение внешней защиты. Reconnect: запрос позиций/ордеров/fills, сверка client keys, reset книги, warmup. До завершения сверки никакого нового ADD.

Reject market/price limit/закрытый рынок: не переходить в Completed; FaultedClosing показывает реальный риск и причину. Оператор использует брокерский терминал/доступные каналы для контроля позиции. Соединение, которого нет, не заменяется фиктивным успешным fill.

Crash: запуск только через recovery, даже если локально был статус Active. Если терминальный checkpoint оказался раньше позднего fill, восстановленный ExitLatch сохраняет запрет на вход.

## Наблюдаемость

Обязательны состояние подключения и последнего события, очередь обработки, data-quality flags, текущая и ожидающая экспозиция, доступный риск, pending/unknown intent count, время начала Closing, retries/query attempts, доминирующая причина запрета.

Логи хранят версии алгоритма/параметров и идентификаторы кампаний без паролей, API keys и персональных реквизитов. Диагностический экспорт отделён от разрешений торгового доступа. Публикация tick datasets и account snapshots в GitHub не требуется и по умолчанию запрещена.

## Путь к live

Engineering gates → historical Research GO/ResearchOnly → shadow без собственных заявок → paper с явным указанием модели fills → ограниченный live только по отдельному разрешению. Shadow не измеряет достоверно позицию нашей заявки в реальной очереди, paper не заменяет реальную проверку коннектора.

Перед live определить допустимые risk/drawdown/turnover ограничения и операционный ответ на отказ. Размер и дата pilot согласуются отдельно; документационный push не является разрешением запускать торговлю или MCP test stand.

## Регрессия и откат

Новый модуль по умолчанию выключен в существующих конфигурациях. Старые файлы настроек не переписываются при чтении. Откат версии при активной кампании допустим только после закрытия либо доказанной совместимости recovery schema; нельзя просто удалить новые state files.

Release artifact включает commit, schema versions, feature flags, approved profile, known limitations, результаты tests/builds, пользовательскую инструкцию и rollback procedure. Статус beta/research/live отражается в UI, а не только в changelog.
