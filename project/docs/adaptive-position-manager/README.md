# Adaptive Position Manager — комплект реализации

Версия спецификации: **0.1**, 25 сентября 2026. Репозиторий: **2Rukin/OsEngine**. База: `master`, коммит `f54de33961d45f73319ae1c7313f2854bcb27398`. Ветка: `docs/adaptive-position-manager`.

**Состояние поставки: документация. Торговый менеджер, новые окна и тесты пока не реализованы.** Согласованное поведение и предлагаемые инженерные решения разделены в документах. Прибыльность не доказана.

## Что строим

Компонент сопровождения одной торговой гипотезы, а не новый сигнал входа и не одноразовую сетку. После входа заданным объёмом менеджер многократно уменьшает и увеличивает позицию. Повторный набор после частичного выхода работает и выше, и ниже первоначального входа. При быстром благоприятном движении можно отложить обычное сокращение; при быстром неблагоприятном — пропустить набор. Защитный выход, окончательная цель и время завершения имеют приоритет над адаптацией.

Основная цепочка: **события → состояние рынка → желаемый объём → риск и разрешения → заявка → реальные исполнения → сверка**. Желаемый объём не равен исполненному.

## В каком порядке получать продукт

| Этап | Результат для пользователя | Задания |
|---|---|---|
| M1 | Диагностический робот в штатном Tester: обратимые циклы, риск, волатильность и импульсы | T01–T07 |
| M2 | Воспроизводимый подбор параметров и отдельный тестовый период | T08 |
| M3 | Доступный по качеству данных OFI-профиль и проверка его добавочной ценности | T09 |
| M4 | Исследовательские модели исполнения из литературы; включение только при доказательствах | T10 |
| M5 | Shadow/paper, восстановление, эксплуатационная приёмка | T11–T12 |

M1 не зависит от наличия стакана, clouds, ZigZag или отдельной ветки Order Flow. M4 не должен задерживать получение M1/M2. Исследовательский модуль с отрицательным результатом допустимо поставить выключенным с отчётом; нельзя выдавать его за улучшение.

## Первое поручение агенту

Прочитать [AGENTS.md](../../AGENTS.md), этот индекс, документы 01–06 и [T01](tasks/T01-feasibility.md). Выполнить только T01, представить карту проверенных событий/методов и блокеров. Далее двигаться по зависимостям, а не реализовывать весь комплект одним неделимым изменением.

Изменение файлов проекта — минимальное. Существующие роботы, TradeGrid, форматы данных и настройки сохраняются. Стенд MCP и реальные торговые подключения не запускать без отдельного явного разрешения. Перед созданием файлов робота подтвердить его каталог в соответствии с правилами форка.

## Что считается успехом

Сначала пользователь воспроизводит циклы «сократил → откат → снова набрал» и видит причину каждого решения. Затем совпадают ядро, Tester и Optimizer при одинаковых данных и настройках. Только после этого оцениваются результаты после издержек, устойчивость параметров и реальное исполнение. Документация, успешная сборка и красивая equity — три разных вида доказательств.
