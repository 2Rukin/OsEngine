# T03. Чистое обратимое математическое ядро

Статус: NOT_STARTED. Зависимость: T02. Gate: QG03. Требования: R02,R03,R04,R09,R10,R11,R12,R14.

## Цель

Реализовать [APM-Target-v0.1](../03-mathematics.md) без WPF, потоков брокера и отправки заявок. Все формулы должны иметь тестируемые входы/выходы и проверенные единицы.

## Работа

FixedScales и адаптивные масштабы; fast/slow volatility; нормированная скорость; обратимая кривая; κstart/κt и прямой минимизатор; FAST-режимы с hysteresis, bounded defer и rearm; lot quantization; preview следующего ADD/REDUCE через тот же policy pipeline. Экспортировать промежуточные значения без выдуманного аддитивного attribution.

Не делать target рекурсивной функцией последнего target через текущий q. Не хранить флаг «этот уровень навсегда использован». Начальный вход и последующие реальные fills остаются отдельными событиями — чистое ядро не объявляет их исполненными.

## Тесты

S01–S04, S08–S13, S22, S25. Минимум 1000 seeded property cases: finite/bounds, mirrored Short, monotonic Qcurve при замороженных признаках, κstart normalization, γ=0 baseline, ν=0 floor, τ→0, rearm на границах, отсутствие дребезга. Проверка γ monotonic только в сформулированных в 03 условиях, а не с одновременно меняющейся нормировкой.

Preview при замороженном snapshot обязан совпадать с первым разрешённым реальным действием на той же цене. Ограничить число шагов поиска и память; отсутствие уровня — явный status.

## Приёмка

Golden q совпадает точно на lot-grid. Diagnostics on/off не меняет решения. Вызовы с одним и тем же состоянием детерминированы. Основные формулы и units проверены reviewer; ошибки блокируют задачу, даже если тесты согласованно повторяют ошибочную формулу. Покрытие ядра соответствует QG03/общему coverage gate.

Артефакты: core, unit/property results, таблица формула→метод→тест, математический review. Далее [T04](T04-campaign-risk.md).
