# T01. Аудит базы и доказательство совместимости

Текущий статус: [work record](../evidence/implementation.md#состояние-заданий). Зависимость: комплект документации. Gate: QG01. Требования: R14,R17,R22.

## Цель

До реализации подтвердить, как именно в выбранном master проходят тики, заявки и исполнения, и какие проверки реально поддерживают Tester/Optimizer. Не ограничиваться справочниками с примерами.

## Входы

[06 — интеграция](../06-osengine-integration.md), [04 — данные](../04-data-contracts.md), project/AGENTS.md, CONTEXT_ROBOTS_ARCHITECTURE, CONTEXT_POSITIONS_AND_RISK, CONTEXT_MCP и действующие вложенные инструкции. База исследования уже зафиксирована в README; при более новом master записать diff влияния, не молча сменить базу.

## Работа

Найти реальные события/методы BotTabSimple для ticks, quotes, initial/add/reduce, cancel, query и частичных fills. Выписать сигнатуры, порядок callbacks, поддерживаемые режимы и ограничения. Проверить, где находится stop-trigger и остаётся ли он активным без UI/при disconnect. Установить, является Market реальным типом коннектора или эмуляцией.

Проследить один tick из файла через TesterServer до робота; один pass Optimizer до того же ядра. Проверить доступность Side, времени, Id, обеих лент одновременно и возможность безопасного повторного увеличения после частичного закрытия. Найти минимальную точку расширения, а не переписывать всё.

Обнаружить test harness/framework и среду сборки. Подтвердить каталог нового робота у пользователя перед созданием кода согласно правилам форка; аудит сам по себе не требует создания робота. Для smoke использовать изолированный harness без реального коннектора.

## Результат

Capability report с таблицей Supported / Unsupported / NotVerified, commit/path/line evidence; карта событий; proposed paths; список adapter tests; реестр блокеров и оценка минимальных изменений. Неподдерживаемая очередь Limit не блокирует математический fixture, но запрещает объявлять его реалистичным execution backtest.

## Приёмка

По каждому методу/потоку есть исходник или выполненный тест. Нет утверждений о готовом OFI/OrderFlow из другой ветки. Старые роботы и настройки не изменены. Все неразрешённые критические ограничения перечислены. QG01 PASS только после фактического минимального smoke; одно чтение Markdown даёт audit progress, не PASS.
