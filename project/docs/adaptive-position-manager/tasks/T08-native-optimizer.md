# T08. Optimizer, диапазоны и walk-forward

Текущий статус: [work record](../evidence/implementation.md#состояние-заданий). Зависимость: T07. Gate: QG08. Требования: R12,R14,R15,R16,R21.

## Цель

Штатный оптимизатор подбирает параметры поведения, а пользователь получает честное сравнение сопровождения. Спецификация: [08](../08-optimization.md).

## Работа

Объявить стандартные параметры с единицами, диапазонами, валидацией и fixed/on/off. Locks не передавать как безусловно оптимизируемые. Сделать immutable manifest каждого pass, отдельные состояния и output; diagnostic preview не запускает WPF на каждом прогоне.

Проверить штатные фазы walk-forward и фильтры через реально имеющиеся API/UI. Записывать все комбинации, ошибки и неуспешные trials. Дополнить штатный результат campaign/mark-to-market метриками, если их нет в стандартном отчёте.

Реализовать B0/B1/A1/A2/A3 сравнение с одними и теми же входами/границами, cost stress и параметрической чувствительностью. Не создавать новый универсальный оптимизатор поверх штатного.

## Тесты

Один pass совпадает с Tester на одинаковых событиях/fills. Fixed значения не подменяются default. Число потоков/порядок запусков не изменяет trace. Невалидные комбинации отклоняются, не корректируются тихо. Фазы, warmup и label cutoff причинны. Проверить, что diagnostics off влияет только на объём отчёта.

## Приёмка

Пользователь выбирает не более трёх параметров первого эксперимента, видит число прогонов, завершает их и воспроизводит выбранный pass в Tester. Есть отдельный untouched/OOS результат, результаты соседних параметров и cost stress. Положительный итог не является обязательным условием Engineering PASS; отсутствие преимущества оформляется ResearchOnly/NO-GO.
