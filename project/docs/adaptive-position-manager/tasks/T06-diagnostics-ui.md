# T06. Диагностика и пользовательский интерфейс

Статус: NOT_STARTED. Зависимости: T03,T04,T05. Gate: QG06. Требования: R13,R18.

## Цель

Пользователь видит фактическую обратимость и причины пропусков, а не только финальную прибыль. Спецификация: [09](../09-interface.md).

## Работа

График A/S/U/NoAddZone, preview, решения и fills разными маркерами, target/fill volume во времени. Короткий status показывает все типы объёма и режим. Постоянные критические кнопки не обрезаются.

Создать отдельные окна «Решения», «Заявки и исполнения», «Кампании», «Качество данных», «Отчёт»; кнопки открывают/активируют их. Любая новая таблица модуля только в отдельном окне. Сортировка чисел/дат, фильтры и export. На графике — snapshot именно того момента, не пересчёт с будущими знаниями.

Диагностика отражает реальный pipeline с κ и clipping. Не выдумывать аддитивный вклад факторов. Любой trade/failure имеет reason code; выключение detailed mode не удаляет необходимый execution audit.

## Тесты

Пройти S01,S02,S08,S09,S19 на UI, различая решение и fill. Переключать chart timeframe, сортировку и окна во время одинакового replay: trace торговли не меняется. Проверить повторное открытие/закрытие окон и отсутствие утечек subscriptions.

DPI/размеры из 09: screenshots для 100/125/150%, компактный 200%. Числовая сортировка включает 2,10,100 и отрицательные значения; long text не перекрывает Close/Stop.

## Приёмка

Пользователь указывает конкретный ADD/SKIP и видит достаточное объяснение. Таблицы и кнопки соответствуют контракту. UI не блокирует event loop и не добавляет самостоятельных торговых вызовов.

Артефакты: screenshots, manual checklist, trace parity diagnostics on/off, UI smoke. Не объявлять GUI проверенным по компиляции XAML. Далее [T07](T07-native-tester.md).
