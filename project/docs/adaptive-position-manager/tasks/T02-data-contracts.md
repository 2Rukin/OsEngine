# T02. Контракты, время и качество данных

Статус: NOT_STARTED. Зависимость: T01. Gate: QG02. Требования: R01,R16,R17.

## Цель

Создать единый поток причинных, валидированных событий для чистого ядра и всех адаптеров. Спецификация: [04](../04-data-contracts.md), [03](../03-mathematics.md).

## Работа

Реализовать версии CampaignSpec, market/position snapshots, Decision, Intent, Fill и manifest. Источник времени передаётся явно; исторические таймеры детерминированы. Денежные величины/цены не проходят через double. Для статистических значений проверяется finite.

Сделать нормализацию пользовательского tick-контракта, стабильный порядок одинаковых timestamps, обработку неизвестного Side и конфликта Id. Не менять существующий parser молча: adapter/валидатор вокруг штатного чтения предпочтителен. Точный смысл MicroSeconds/Id подтвердить, не угадывать.

Создать маленькие искусственные fixtures и schedule с явной точностью времени, отдельные от пользовательского SRU6. Определить freshness/warmup, reset сессии, missing windows и capabilities. В TradeOnly недоступность OFI показывать как Missing, а не нейтральное давление.

## Тесты

S23–S25: UnknownSide, нулевой объём окна, отрицательный/некратный объём, отсутствие стоимости шага, неверная валюта, одинаковые времена, дубли, конфликт Id, позднее событие, reset книги/сессии. Проверить exact round-trip decimal/Id через настройки/экспорт. Префикс датасета должен давать те же решения до cutoff, что и полный файл: будущие строки не влияют на прошлое.

## Приёмка

Ни один невалидный ввод не разрешает новый риск. Качество источника видно в snapshot/manifest. Один и тот же fixture даёт один и тот же ordered event stream. Схемы документированы и проверяются негативными тестами. Никакой торговый ордер этой задачей не отправляется.

Артефакты: contracts, fixture manifest, отчёт parser/ordering/freshness tests, реальные build/test команды. Далее [T03](T03-mathematical-core.md).
