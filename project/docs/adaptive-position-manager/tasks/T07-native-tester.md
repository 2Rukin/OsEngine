# T07. Штатный Tester и первая приёмка продукта

Текущий статус: [work record](../evidence/implementation.md#состояние-заданий). Зависимости: T02–T06. Gate: QG07. Требования: R01–R04,R07,R09,R10,R14,R16,R22.

## Цель

Запустить менеджер именно в Tester этого форка, а не показать отдельную красивую симуляцию. Результат — M1, доступный пользователю.

## Работа

Создать тонкий зарегистрированный исследовательский робот в согласованной папке. Дать штатные параметры, выбор сохранённого CampaignSchedule, начальный вход и вызов того же ядра. Интегрировать диагностику из T06. Не отключать обработку в IsOsOptimizer заранее.

Подготовить маленький импортируемый датасет, входные сценарии и инструкцию кнопками по фактическому интерфейсу. Сохранить профиль GoldenFixture отдельно от NativeTester. Протокол указывает fill model, commissions/slippage и все несовместимые возможности.

Прогнать исторические тики пользователя только после validation; не публиковать исходный набор в Git. Не исследовать весь контракт как одинаково ликвидный без пользовательского выбора периода; автоматическую склейку/роллирование не добавлять.

## Тесты

S01/S02 end-to-end с таблицей q; S05/S06/S07 и импульсы; S22 десять повторов/разная скорость/diagnostics toggles. Для особенностей нативных fills ожидаемый trace строится по подтверждённым событиям, не выдуманным ценам fixture. Прогнать cost базовый/×1.5/×2. Проверить старый контрольный робот и старые settings при выключенном APM.

## Приёмка

Пользователь запускает сохранённый сценарий и видит «сократил → откат → вновь набрал» в обеих зонах. Получает pause, график, окна, отчёт. Режим без нужных capabilities честно отклонён. Решения не зависят от скорости проигрывания. Сборка/тесты фактически выполнены на поддерживаемой Windows-среде.

Артефакты: manifest, scenario files, actual trace, screenshots, capability limitations, кнопочная инструкция. MCP stand не запускать без отдельного разрешения. Далее [T08](T08-native-optimizer.md).
