# T05. Исполнение через штатный адаптер

Статус: NOT_STARTED. Зависимости: T01,T02,T04. Gate: QG05. Требования: R01,R08,R11,R13,R19.

## Цель

Переводить решения в настоящие команды OsEngine без дублей, избыточного закрытия и смешивания чужих позиций. Спецификация: [05](../05-state-execution.md), подтверждённые hooks из T01.

## Работа

Один владелец ordinary intents, client keys и журнал до send. Сопоставление ack/fill/cancel/reject, учёт частичных исполнений и uncertain status. Реализовать Market и ограниченный Limit режим на реально доступных API. MaxChildVolume относится к обычной ребалансировке; защита не должна ждать обыкновенных пауз.

Обработать cancel/replace и изменение target при pending order. Защитный путь закрывает подтверждённый незарезервированный остаток и поздние fills, не дублирует другой close. Не использовать Unsafe методы без явного подтверждения, что штатные альтернативы непригодны, и отдельных invariant tests.

Не пытаться реализовать полноценный exchange simulator в этом задании. Fake broker нужен для проверки поведения с заданными событиями; экономика нативного исполнения оценивается отдельно.

## Тесты

S15–S21. Перестановки ack-before-fill/fill-before-ack/cancel-race; duplicate fills; reject; timeout без известного результата; late fill после stop и после Completed; частичное закрытие одновременно с emergency. Проверить маршрутизацию short reduce, запрет переворота, ownership и отсутствие команд всему счёту.

## Приёмка

Каждый fill учтён ровно один раз согласно гарантии Id источника. Неизвестное исполнение не повторяется вслепую. Максимальный разрешённый собственный риск включает working/unknown increase. Видны фактически оставшаяся позиция и неуспешное закрытие. Самостоятельный новый broker transport не создан.

Артефакты: adapter capability tests, fault-injection report, sequence race cases, trace intents/fills, build. Для live отправки отдельное разрешение; текущая задача может полностью проверяться без реального счёта. Далее [T06](T06-diagnostics-ui.md).
