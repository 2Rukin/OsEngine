# 01. Продуктовый контракт

Статус: поведение из обсуждения — обязательное; числовые значения в примерах — тестовые, не торговые рекомендации. Навигация: [индекс](README.md).

## Пользовательская задача

Пользователь выбирает направление и торговую гипотезу. Менеджер входит заданным объёмом, продаёт часть лонга при благоприятном движении, восстанавливает её при откате, усредняет в допустимой неблагоприятной области и сокращает добавленный объём при отскоке. Цикл повторяется, пока гипотеза активна. Для шорта действия зеркальны.

Термин «кампания» означает весь интервал от принятия одного сценария входа до подтверждённого завершения всех его заявок и позиции. Частичный выход не создаёт новую кампанию. Отдельные исполнения не считаются независимыми выигрышными сделками для оценки всей стратегии.

## Обязательные требования

| ID | Контракт |
|---|---|
| R01 | Начальный вход заданным InitialVolume; риск проверяется до отправки, фактический объём — только по исполнениям |
| R02 | Частичное сокращение при благоприятном движении без обязательной немедленной полной разгрузки |
| R03 | После частичного выхода откат повторно разрешает увеличение позиции; уровни не расходуются навсегда |
| R04 | Те же обратимые циклы работают ниже исходного входа для лонга и выше него для шорта |
| R05 | Полная окончательная цель, HardStop и окончание времени завершают кампанию; автоматического повторного входа по старому сигналу нет |
| R06 | HardStop фиксируется до входа и не отодвигается после усреднения или роста волатильности |
| R07 | NoAddZone запрещает увеличение, но не мешает сокращению и защитному выходу |
| R08 | MaxVolume, денежный риск и лимиты заявки учитывают потенциально исполнимые собственные заявки |
| R09 | FAST_FAVORABLE допускает пропуск обычных сокращений с ограничением времени ожидания; окончательная цель не пропускается |
| R10 | FAST_ADVERSE запрещает усреднение; пропущенные покупки не накапливаются в долг |
| R11 | Пересечение нескольких виртуальных уровней создаёт одно актуальное решение, не очередь устаревших действий |
| R12 | Шаги, доступный объём и режим адаптируются к проверяемым данным; hysteresis исключает переключения на каждом шумовом тике |
| R13 | Каждое действие и отказ имеют причину; отображаются желаемый, разрешённый, исполненный и ожидающий объёмы |
| R14 | Один и тот же расчётный код используется в сценарных тестах, Tester, Optimizer и live-адаптере |
| R15 | Параметры поведения доступны штатному Optimizer; защитные ограничения не превращаются в свободные параметры поиска |
| R16 | Нет данных из будущего; повторный прогон идентичного манифеста воспроизводим |
| R17 | TradeOnly не имитирует OFI и глубину; отсутствие требуемого источника явно блокирует профиль |
| R18 | Таблицы открываются кнопками в отдельных окнах; основные кнопки остаются видимыми при согласованном размере окна и DPI |
| R19 | Частичные исполнения, отмена, отказ, потеря связи и рестарт не приводят к слепым повторам заявок |
| R20 | Позиция внутридневная; горизонт может составлять часы, а не навязанные несколько минут |
| R21 | Оценивается вся кампания после комиссий, открытая просадка и вклад адаптации относительно базового сопровождения |
| R22 | Существующие роботы, TradeGrid и прежние пользовательские настройки не меняют поведения при выключенном новом компоненте |

## Входной сценарий

Обязательны Instrument, Account, CampaignId, Direction, InitialVolume, MaxVolume, HardStopPrice, FinalTargetPrice, RiskBudgetCurrency, StopSlippageReserveTicks, SessionExitTime и профиль данных. Валюта риска должна совпадать с валютой расчёта либо требовать проверенного конвертера; молчаливый курс 1:1 запрещён.

EntrySignalId идентифицирует единственный исходный сигнал. Первый вход в исследовательском режиме приходит из заранее сохранённого сценария с датой/временем, направлением и границами. Менеджер не придумывает «прибыльный» вход сам.

Начальный ориентир для preflight задаёт сценарий. После завершения/отмены остатка начальной заявки AnchorPrice фиксируется по её фактическим исполнениям и далее не меняется. AverageEntry текущей позиции, AnchorPrice и безубыточность всей кампании — разные значения. Если после исполнения нарушено расположение границ, остаток входа отменяется, включается защитное завершение.

## Обратимость

При одинаковом рыночном состоянии возврат цены к прежней области должен снова допускать соответствующий объём. Если изменились волатильность, риск, доступность данных или режим, разрешённый объём может отличаться. В интерфейсе должна быть видна конкретная причина отличия; «уровень уже использован» не является основанием.

В минусовой зоне сокращение допустимо и при отрицательном результате относительно средней цены. Нельзя блокировать его условием «продавать только с прибылью»: это разрушит описанный пользователем цикл. При этом нельзя объявлять такое сокращение прибылью последних усреднений без отдельно определённого учёта лотов.

## Приоритеты

Ручное аварийное завершение, HardStop, денежный стоп и обязательное окончание сессии выше всех обычных решений. Достижение FinalTargetPrice запускает окончательное закрытие независимо от FAST_FAVORABLE. Затем идут сверка/доступность данных, ограничения риска, запреты набора, hysteresis и обычное сопровождение.

HardStop — уровень запуска защитного закрытия, а не гарантия цены или максимального убытка. При разрыве, отсутствии ликвидности, остановке торгов или отключении терминала фактическое исполнение может быть хуже расчётного.

## Границы первой поставки

M1: один инструмент и одна направленная кампания на выделенном табе; TradeOnly; детерминированная кривая и адаптация к волатильности/скорости; ручные или заранее записанные входы; диагностический интерфейс. Нет мартингейла, переворота позиции, overnight, автоподбора контрактов, обязательной зависимости от других веток и нейросети.

Сигналы clouds/VWAP/ZigZag в будущем подключаются через внешний контекст. Их наличие на master не предполагается. Автоматический перенос нижней границы, автоматический новый вход после выхода в ноль и максимизация риска ради доходности не входят в контракт.

## Продуктовые критерии

Пользователь воспроизводит S01–S04 из [сценариев](07-tester-scenarios.md), без чтения исходников объясняет ADD/REDUCE/SKIP и подтверждает конечную остановку. Затем принимает M2 по честному сравнению на новых данных. Допуск к реальным деньгам — отдельная эксплуатационная приёмка, не следствие согласия с этим документом.
