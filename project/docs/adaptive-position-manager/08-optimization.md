# 08. Подбор параметров и исследовательский протокол

Совместимость со штатным Optimizer — обязательная цель, не обещание уже выполненного прогона. Основания и ограничения: [06](06-osengine-integration.md). Результаты оцениваются по всей кампании, не только прибыльным частичным выходам.

## Три разных вида параметров

| Группа | Примеры | Правило |
|---|---|---|
| Защитные locks | HardStop/FinalTarget сценария, RiskBudget, MaxVolume, SessionExitTime, аварийные правила | Не оптимизировать по доходности; изменение требует нового утверждённого сценария |
| Политика поведения | Wadd/Wreduce или kadd/kreduce, γinv, FAST On/Off, rearm, deadband, MinRebalanceVolume | Разрешён ограниченный поиск внутри locks |
| Оценивание | Warmup, half-life, коэффициенты OFI/depth, модель исполнения/ликвидности | Калибровать только на прошлых данных с версией; не выдавать коэффициент fit за универсальную константу |

InitialVolume — вход сценария. Для исследования размеров можно создать отдельные risk-normalized сценарии; нельзя скрыто менять его в одном сравнении и приписывать прирост адаптации. Поведенческий VolumeCap, если добавлен, всегда ≤ жёсткого MaxVolume. Сам MaxVolume остаётся защитным lock.

## Начальный небольшой поиск

Сначала FixedScales + γinv=0 + FAST off — baseline. Затем включать по одному фактору. Для первого поиска выбрать не более трёх поведенческих параметров и не более пяти заранее заданных значений каждого: до 125 комбинаций на фазу. Это ограничение исследовательской дисциплины, не лимит OsEngine.

Кандидаты: kadd, kreduce, RearmVolFactor; на следующем эксперименте γinv и FAST thresholds. Невалидные комбинации On≤Off, W≤0, lot mismatch отбрасываются preflight, а не исправляются автоматически. Значения и единицы видны в UI и отчёте. Закрытые расходы/locks не должны становиться активными чекбоксами поиска.

## Сравниваемые варианты

| Вариант | Изменение относительно исходного входа |
|---|---|
| B0 | Постоянный начальный объём до того же stop/target/session exit |
| B1 | Обратимая фиксированная кривая, без адаптивных признаков |
| A1 | B1 + волатильность |
| A2 | A1 + фильтры FAST и hysteresis |
| A3 | A2 + нормированный inventory penalty |
| A4 | A3 + проверенный OFI/книжный профиль |
| A5 | Выбранная политика + исследовательское адаптивное исполнение |

Для всех вариантов одинаковые заранее зафиксированные входы, границы и максимальный риск. Дополнительно показывать фактическую среднюю/максимальную экспозицию и капитал: одинаковый cap не означает одинаковый реально взятый риск. Не смешивать улучшение входного сигнала с улучшением сопровождения.

## Разделение времени

Данные разделяются хронологически на train, validation и финальный untouched test до запуска оптимизации. Границы кампаний не разрывать между выборками; окна с перекрывающимися labels очищаются от пересечения. Embargo не меньше максимального forward-label horizon, если такие labels используются. Warmup из прошлого допустим, но не создаёт тестовые сделки до начала контрольного интервала.

Walk-forward: fit/выбор на прошлом интервале → проверка на следующем → сдвиг окна. Длины определяет объём доступных независимых сессий и фиксирует experiment manifest, а не календарный пример из чата. Итоговая OOS equity составляется из неперекрывающихся контрольных отрезков. Параметры между фазами могут меняться, но каждая смена объясняется протоколом.

Online обновление estimator в test допускается только при заранее объявленном causal prequential-протоколе: действие делается по старой версии, метка созревает позже, затем update. Тюнинг гиперпараметров по уже просмотренному test превращает его в validation; нужен новый holdout.

## Критерии отбора

Сначала отбрасывать нарушения функциональных gates, невалидные данные, нехватку риск-cap, незавершённые кампании и недостаточный объём наблюдений. Экономический профиль определяет до эксперимента допустимые drawdown, tail loss, оборот и минимальное число независимых сессий. Незаполненный профиль означает **ResearchOnly**, а не разрешение торговать.

Основной показатель: разница net PnL на кампанию/единицу утверждённого риска относительно выбранного baseline. Обязательно дополнить открытой peak-to-trough просадкой, худшей кампанией, хвостовыми потерями, временем в позиции, оборотом, средним/максимальным q и комиссионной нагрузкой. Процент побед, Profit Factor и реализованная equity в одиночку недостаточны.

Доверительные интервалы оценивать блоками по сессиям/кампаниям, не переставляя каждый микрофилл как независимую сделку. Учитывать число испробованных конфигураций и экспериментов. Малый sample отмечается как недостаточный, а не округляется до уверенного вывода.

## Устойчивость и stress

Показать соседние наборы параметров и карту результатов, а не только вершину. Плато — полезная диагностическая гипотеза, но не доказательство отсутствия переобучения. Повторить cost ×1.5/×2, ухудшение fill assumptions, задержки и пропуски данных. Разделить сессии по характеристикам, вычисленным без будущего; отдельно показать трендовые против позиции участки и частые стопы.

Ablation каждого признака обязательна. Если OFI/сложное исполнение не даёт устойчивого улучшения после издержек, оно остаётся выключенным. Этим можно успешно завершить исследовательскую задачу, но нельзя заявить экономический GO.

## Выходные артефакты

Experiment manifest, список всех комбинаций и отказов, параметры каждого pass, phase boundaries, dataset hashes, canonical decision hashes, результаты кампаний, net/mark-to-market equity, cost stress, сравнение с baseline, карта чувствительности, калибровка и её training cutoff, заключение GO / ResearchOnly / NO-GO.

Все таблицы открываются по кнопкам в отдельных окнах, экспорт доступны в CSV/JSON. Штатный Optimizer отвечает за перебор; дополнительный отчёт APM хранит отсутствующие в штатной статистике campaign/diagnostic метрики. Не подменять отсутствующие метрики нулями.
