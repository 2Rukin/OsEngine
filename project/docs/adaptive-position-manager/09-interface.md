# 09. Интерфейс и объяснимость

Это спецификация новых элементов, не инструкция к уже установленному роботу. Цель — пользователь понимает действие без чтения C# и без гадания по equity. Индекс: [README](README.md).

## Главное рабочее окно

Основная площадь — график цены. На нём неизменяемые Anchor/HardStop/FinalTarget, NoAddZone, актуальные preview ADD/REDUCE и маркеры решений/фактических исполнений. Решение и fill изображаются различно, даже если совпадают по времени. Пропущенный уровень не рисуется исполненной сделкой.

Короткая панель состояния: CampaignId, направление, статус/ExitLatch, профиль данных/readiness, Filled, RawTarget, RiskAllowedTarget, Pending, AverageEntry, текущий риск/бюджет, режим рынка и ближайшая причина блокировки.

Отдельная линия/область объёма показывает FilledVolume и разрешённый target во времени. График не изменяет расчётный timeframe: переключение свечей — только визуализация уже рассчитанных событий.

## Постоянные кнопки

«Начать сценарий», «Пауза набора», «Продолжить», «Закрыть кампанию», «Аварийное закрытие», «Решения», «Заявки и исполнения», «Кампании», «Качество данных», «Параметры», «Отчёт». Разместить с переносом/адаптивной компоновкой, не прятать критические действия в обрезанную область. Различать обычную остановку подачи сигналов и фактическое закрытие позиции.

Окно параметров использует поля/группы. Если параметры представлены таблицей, она также открывается отдельным окном. Новые embedded tables на главном графике запрещены.

## Отдельные окна

| Кнопка | Содержание |
|---|---|
| Решения | EventTime/sequence, цена, q до/после, Raw/Policy/Allowed, режим, action, все reason codes |
| Заявки и исполнения | Intent, клиентский/брокерский ID, side/type, sent/ack/cancel/fill, остаток, фактическая цена и slippage |
| Кампании | Вход/выход, net result, открытая просадка, qmax, оборот, причина завершения |
| Качество данных | Источник/точность времени, unknown side, duplicate/conflict/gap counters, capabilities, warmup |
| Отчёт | Baseline comparison, OOS/stress, ограничения и gate status |

Сортировка по заголовку в обе стороны; числовые значения сортируются численно, даты — по времени, а не локализованной строке. Фильтры по CampaignId, action, reason и интервалу. Export отражает фильтр и исходные единицы. Закрытие окна не меняет торговлю; повторное открытие не создаёт дублирующую подписку.

## Объяснение решения

Показывать последовательность преобразований: Qcurve → применение κ → RawTarget → hysteresis/режим → risk cap → pending adjustment → запрошенный объём → fills. Это не всегда аддитивная модель. Нельзя выдумывать разложение «цена +2, OFI +1, риск −3», если реальные формулы нелинейны или выполнен hard clip.

Коды причин имеют стабильные машинные имена и русские объяснения: INITIAL_ENTRY, RESTORE_AFTER_REDUCE, AVERAGE_ADVERSE, REDUCE_ON_REBOUND, FAST_FAVORABLE_DEFER, FAST_ADVERSE_NO_ADD, NO_ADD_ZONE, RISK_CAP, MAX_VOLUME, REARM_PENDING, PENDING_ORDER, DATA_NOT_READY, HARD_STOP, FINAL_TARGET, SESSION_EXIT, EXECUTION_UNKNOWN, LATE_FILL, RECONCILIATION_REQUIRED.

Показывать все сработавшие ограничения и отдельно доминирующую причину. Например, отсутствие ADD одновременно из-за NoAddZone и stale-book не следует объяснять только нейтральным режимом рынка.

## Просмотр прошлого

Выбор строки решения перемещает график к event sequence и восстанавливает snapshot, который был известен тогда. Уровни не пересчитываются задним числом по сегодняшней калибровке. Последняя незавершённая структура внешнего ZigZag не выдаётся за уже подтверждённую.

Replay/Tester и live имеют одинаковые обозначения, но явную плашку режима и fill model. Прогон TradeOnly не должен отображать фиктивный стакан. SyntheticFixture помечается «проверка поведения, исполнение условное».

## Приёмка экрана

Проверить минимальную объявленную рабочую область не больше 1280×720 физических пикселей при 100%, 125%, 150% DPI; при 200% допускается компактная компоновка и меньший график, но все критические кнопки доступны без обрезки. Фактические размеры/DPI фиксируются screenshots, а не оценкой разработчика по XAML.

Поддержать изменение размера и раскрытие нескольких окон таблиц без остановки событий. Проверить русские подписи, длинные причины и instrument names. Сортировка таблицы не меняет исходный порядок событий, экспорт trace и хэши расчёта.
